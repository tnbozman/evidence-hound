    Microsoft 365 collector¶

    The built-in m365 collector reads a Microsoft 365 tenant through Microsoft Graph, read-only, and reports framework-neutral checks for identity, privileged access, device compliance and Office hardening. Every Graph collection it reads is saved as JSON evidence, with personal data hashed.

    It signs in as an Entra app registration with application permissions (client credentials). It never signs in as a person, and it never writes to the tenant.

    To try it on a test tenant first, follow the local trial: it registers this collector with hound add collector m365 and runs it next to a local CISO Assistant.

    1. Register the app¶

    In the Microsoft Entra admin center, as a Global Administrator or Privileged Role Administrator:

    1. Identity > Applications > App registrations > New registration. Name it, for example Evidence Hound collector. Supported account types: Accounts in this organizational directory only. No redirect URI.
    2. Note the Application (client) ID and the Directory (tenant) ID from the Overview page. They become the client_id and tenant_id settings.
    3. API permissions > Add a permission > Microsoft Graph > Application permissions. Add the six permissions below, then Grant admin consent. Remove the default delegated User.Read; the collector does not use it.
    4. Certificates & secrets. Upload a certificate (preferred, see below) or create a client secret.
    5. Optional but recommended: in Enterprise applications, open the app and set Assignment required to Yes, and in Conditional Access restrict the app's sign-ins to the host that runs the collector (a workload identity policy, if licensed).

    Permissions¶

    All are read-only application permissions. Nothing else is needed.

    Permission Used for Graph requests
    User.Read.All Which accounts are enabled members, and which are synchronised from on-premises. v1.0/users
    AuditLog.Read.All Which users are MFA-capable, from the authentication methods registration report. v1.0/reports/authenticationMethods/userRegistrationDetails
    Policy.Read.All Conditional Access policies: MFA, legacy authentication, authentication strengths. v1.0/identity/conditionalAccess/policies
    RoleManagement.Read.Directory Who holds directory roles, and whether they are eligible (PIM) or permanent. v1.0/roleManagement/directory/roleAssignments, roleEligibilitySchedules, roleAssignmentScheduleInstances
    DeviceManagementManagedDevices.Read.All Intune-managed devices: operating system, build and compliance state. v1.0/deviceManagement/managedDevices
    DeviceManagementConfiguration.Read.All Intune policies: Office macro settings, attack surface reduction rules, App Control for Business policies and AppLocker custom profiles. v1.0/deviceManagement/deviceConfigurations, beta/deviceManagement/configurationPolicies
    ThreatHunting.Read.All Microsoft Defender for Endpoint advanced hunting: application control events, the most-blocked files, and which Windows devices are onboarded. Three fixed queries, each sent as a POST with a // evidence-hound: <name> first line so the tenant's audit log shows which query ran. POST v1.0/security/runHuntingQuery

    Only for hound onboard environment --graph (see onboarding): Organization.Read.All, to read the subscribed licences (v1.0/subscribedSkus). Collection never uses it; leave it out if you record the signals another way.

    The sprint plan listed Reports.Read.All; the registration report actually needs AuditLog.Read.All, and Reports.Read.All is not used.

    Licences: Conditional Access and the registration report need Microsoft Entra ID P1. Privileged Identity Management needs Entra ID P2 or ID Governance; without it the PIM collections are skipped and the PIM check reports not_applicable. The Intune checks need Intune. The application control events check needs Microsoft Defender for Endpoint Plan 2 (or Microsoft 365 E5 or Defender for Business), which brings advanced hunting; without it, or without ThreatHunting.Read.All, the run still succeeds and only that check says why (not_applicable for the licence, error for the permission).

    Certificate (preferred)¶

    A certificate cannot be phished or pasted into the wrong place as easily as a secret, and its private key never leaves the collector host. Create one on that host (or wherever you keep keys):

    $ openssl req -x509 -newkey rsa:3072 -sha256 -days 365 -nodes \
    -keyout hound-m365-private.pem -out hound-m365.crt -subj "/CN=Evidence Hound collector"
$ cat hound-m365.crt hound-m365-private.pem > hound-m365.pem
$ chmod 600 hound-m365-private.pem hound-m365.pem
    1. Upload hound-m365.crt (the public certificate only) under Certificates & secrets > Certificates.
    2. Give the collector hound-m365.pem (certificate followed by its unencrypted private key) as the client_certificate secret, for example as a Docker secret: client_certificate: file:/run/secrets/hound_m365_pem.
    3. Delete hound-m365-private.pem once the PEM is stored. Put a reminder in CISO Assistant (a recurring task) to renew the certificate before it expires.

    Client secret¶

    If a certificate is not practical, create a client secret under Certificates & secrets > Client secrets with the shortest expiry you can manage, and give it as the client_secret secret, for example client_secret: env:HOUND_M365_CLIENT_SECRET. When both secrets are set, the certificate is used.

    2. Configure the collector¶

    collectors:
  - name: example-m365
    type: m365
    schedule: "0 3 * * *"                     # daily, 03:00 UTC
    settings:
      tenant_id: 00000000-0000-4000-8000-00000000e001
      client_id: 00000000-0000-4000-8000-00000000c001
      break_glass_accounts: 00000000-0000-4000-8000-0000000000b1, 00000000-0000-4000-8000-0000000000b2
      supported_windows_builds: 10.0.22631, 10.0.26100
    secrets:
      client_certificate: file:/run/secrets/hound_m365_pem

    The IDs above are made up. Keep your real tenant and client IDs in your private deployment config, never in this repo.

    Setting Required Meaning
    tenant_id yes Directory (tenant) ID.
    client_id yes Application (client) ID of the app registration.
    supported_windows_builds yes Comma-separated Windows builds still in support, as the first three parts of the version (10.0.26100 is Windows 11 24H2). Review it when Microsoft ends support for a release.
    break_glass_accounts no Comma-separated object IDs of break-glass (emergency access) accounts. Conditional Access policies may exclude these and nothing else.
    graph_url no Microsoft Graph address. Default https://graph.microsoft.com/. Next pages are only followed on this host.
    sign_in no app (the default) signs in as the app registration, with its certificate or secret. none sends no credential, for the Microsoft 365 dev server only: it is accepted only when graph_url is on localhost, 127.0.0.1 or [::1], and refused otherwise (m365.sign_in_not_loopback).
    system no The system in scope/setup.yaml this instance collects from, such as Example 365. With it, scope/capabilities.yaml can say which capabilities Microsoft 365 provides (see Capabilities).
    include_identities no true keeps user principal names, mail addresses, people's names and device names in evidence. Default false: they are hashed.
    mfa_partial_percent no MFA-capable share of members at or above which MFA registration is partial rather than fail. Default 90.
    privileged_roles no Comma-separated role template IDs treated as privileged. Default: the 14 built-in roles listed under the checks below.
    global_admin_min no Fewest Global Administrators expected, break-glass accounts included. Default 2.
    global_admin_max no Most Global Administrators expected, break-glass accounts included. Default 4.
    compliant_pass_percent no Compliant share of managed Windows devices needed to pass. Default 95.
    compliant_partial_percent no Compliant share needed for partial. Default 80.
    application_control_window_days no Days of application control events the events check reads, 1 to 30 (advanced hunting keeps 30). Default 30.
    defender_onboarded_percent no Share of Intune-managed Windows devices onboarded to Defender for Endpoint needed for the events check to pass. Default 95.
    application_control_groups no Comma-separated group IDs an enforced application control policy must be assigned to, when none is assigned to all devices. Without it, application control assigned only to groups is partial.
    Secret Meaning
    client_certificate PEM certificate and private key of the app registration (preferred).
    client_secret Client secret, if no certificate is used.

    hound config validate checks the required settings; hound config validate --check-secrets also resolves the secret references. The collector itself reports every bad setting at once (m365.setting_missing, m365.setting_invalid) before it makes any request.

    3. Dry run¶

    $ hound config validate --check-secrets hound.yaml
valid
$ hound collect --config hound.yaml --dry-run

    A first run that fails with m365.graph_forbidden names the permission that is missing or not consented. m365.auth_failed means the tenant, client ID or credential is wrong, or the certificate has expired.

    Checks¶

    Check ID Measures Outcomes Limits
    identity.mfa.registered_all_users Enabled member accounts that the registration report marks MFA-capable. Guests and disabled accounts are not counted. pass at 100 %; partial at or above mfa_partial_percent; else fail. An account missing from the report counts as not capable. The report can lag changes by up to a day.
    identity.mfa.enforced_conditional_access An enabled Conditional Access policy for all users and all cloud apps that requires MFA (the MFA control or an authentication strength, alone or combined with AND). pass when such a policy excludes only break_glass_accounts; fail naming any other excluded user, group or role; fail when there is none. Report-only policies do not count. Exclusions of guests or external users are not read yet. Conditions such as locations or platforms are not assessed.
    identity.legacy_auth_blocked An enabled policy for all users and all cloud apps that blocks the Exchange ActiveSync and "other" client app types. As above. Same as above.
    identity.mfa.phishing_resistant_admins Enabled policies requiring the built-in Phishing-resistant MFA authentication strength, and which privileged roles they cover. pass for every privileged role; partial naming roles not covered; fail for none. Custom authentication strengths are not recognised, even if phishing-resistant.
    identity.privileged.global_admin_count Accounts holding Global Administrator, active or eligible. pass within global_admin_min to global_admin_max; else fail. A group assigned the role counts as one holder.
    identity.privileged.admins_cloud_only Whether user accounts holding privileged roles (active or eligible) are cloud-only rather than synchronised from on-premises. pass when none is synchronised (groups and apps holding roles are noted, not assessed); fail naming synchronised accounts. Members of role-assignable groups are not expanded.
    identity.privileged.pim_eligible_not_permanent Whether privileged roles are held as eligible (activated just in time) rather than permanently assigned. pass when no permanent privileged assignment exists apart from break-glass accounts; fail naming them; not_applicable without PIM. Time-bound active assignments count as not permanent.
    endpoint.managed.compliant_ratio Share of Intune-managed Windows devices whose compliance state is compliant. pass at compliant_pass_percent; partial at compliant_partial_percent; else fail. No managed Windows devices fails. Devices in grace period count as not compliant. Devices not enrolled in Intune are not seen.
    endpoint.os.supported_versions Every managed Windows device runs a build in supported_windows_builds. pass, or fail listing unsupported builds with counts. No managed Windows devices fails. Checks the build, not the monthly patch level.
    apps.office.macros_blocked_from_internet An assigned Intune settings catalog policy enables Block macros from running in Office files from the Internet for Word, Excel and PowerPoint. pass when all three are assigned to all users; partial when only some apps are, or only through groups; else fail. Group Policy, the Cloud Policy service and Administrative Templates profiles are not read. Exclusion groups are not subtracted from "all users".
    endpoint.asr.office_rules_enabled The four Office attack surface reduction rules (Office child processes, executable content, code injection, Win32 API calls from macros) in block mode, in a settings catalog policy or endpoint protection profile assigned to all users or all devices. pass when all four block for all users or devices; partial when some block, are in audit or warn mode, or block only for some groups; fail when none is configured. Rules set by Group Policy or Defender for Endpoint security settings management are not seen. Per-device rule state is not read.
    endpoint.application_control.enforced An assigned App Control for Business policy (Intune endpoint security, found by its template family endpointSecurityApplicationControl) or AppLocker custom profile (OMA-URI ./Vendor/MSFT/AppLocker/ApplicationLaunchRestrictions/{Grouping}/{EXE,DLL,Script,MSI}/Policy) in enforced mode. pass when an enforced policy is assigned to all devices or to every group in application_control_groups; partial when policies are only in audit mode, their AppLocker values come back encrypted, or they cover only some groups; fail when none is assigned. Policies set by Group Policy, or by a custom profile using the ApplicationControl CSP, are not seen. App Control for Business mode is read from its built-in controls choice (..._enable_app_control_0 enforce, _1 audit) or Enabled:Audit Mode in uploaded XML: these IDs are still to be confirmed against a real export. Exclusion groups are not subtracted.
    endpoint.application_control.events_centrally_logged Defender for Endpoint advanced hunting: DeviceEvents with an AppControl… or AppLocker… action type over application_control_window_days, counted by device and action, the 20 most-blocked files, and the latest OnboardingStatus of each Windows device from DeviceInfo. pass when events arrived and at least defender_onboarded_percent of Intune-managed Windows devices are onboarded; partial when events arrived but fewer devices are onboarded; fail when no events arrived; not_applicable without an advanced hunting licence; error when the permission is missing. Events sent only to a SIEM or Windows Event Forwarding, not Defender, are not seen: record those with the manual application control event log template. Whether the events are reviewed is not judged.
    endpoint.application_control.file_types_covered Which file types enforced policies control: executables, software libraries, scripts and installers. App Control for Business covers all four by design; AppLocker needs the EXE, DLL, Script and MSI rule collections with EnforcementMode="Enabled". pass when all four are covered; fail naming the missing types. As above. An AppLocker collection whose value Graph returns encrypted counts as not covered.

    Default privileged roles: Global Administrator, Privileged Role Administrator, Privileged Authentication Administrator, Security Administrator, Conditional Access Administrator, Exchange Administrator, SharePoint Administrator, User Administrator, Authentication Administrator, Application Administrator, Cloud Application Administrator, Intune Administrator, Helpdesk Administrator and Billing Administrator.

    Capabilities¶

    The checks are grouped by the capability they judge, using the Essential Eight mitigation codes that scope/capabilities.yaml uses:

    Capability Checks
    mfa multi-factor authentication identity.mfa.registered_all_users, identity.mfa.enforced_conditional_access, identity.legacy_auth_blocked, identity.mfa.phishing_resistant_admins
    rap restrict administrative privileges identity.privileged.global_admin_count, identity.privileged.admins_cloud_only, identity.privileged.pim_eligible_not_permanent
    pos patch operating systems endpoint.managed.compliant_ratio, endpoint.os.supported_versions
    rmom restrict Microsoft Office macros apps.office.macros_blocked_from_internet, endpoint.asr.office_rules_enabled
    uah user application hardening endpoint.asr.office_rules_enabled
    ac application control endpoint.application_control.enforced, endpoint.application_control.file_types_covered, endpoint.application_control.events_centrally_logged

    When the deployment names its scope folder (scope: in hound.yaml) and that folder has a capabilities.yaml, each run tells the collector which capabilities another product provides. A check whose every capability is provided elsewhere reports not_applicable, and its observation names the product and its audit, such as "Not judged on Microsoft 365: scope/capabilities.yaml records mfa as provided by Example identity provider (audit EX-IDP-E8-2026)." So a third-party product, such as an application control or identity product, is never reported as a Microsoft 365 failure. A check that serves two capabilities, such as the ASR Office rules, runs while Microsoft 365 provides either.

    A mitigation is this instance's when its route names the instance, or its systems include the instance's system setting. Manual evidence and gaps are never the collector's. A system decision with no route counts as another product's only when the instance's system is set, so without a map, or without system and routes, every check runs as before.

    hound onboard environment --graph <this collector> reads the tenant's licences and Intune configuration kinds read-only, as this instance, and suggests Microsoft 365 for the mitigations they cover. Nothing is enabled until you accept: an accepted suggestion is written with evidence: collector and route: <this collector>; naming another product instead routes that mitigation away from Microsoft 365.

    Evidence¶

    Each run writes one JSON file per Graph collection, with the request, the number of pages read, and every item. Check results cite the files they read.

    File Contents
    users.json Users: ID, enabled, member or guest, synchronised or cloud-only.
    mfa-registration.json Registration details: MFA-capable, registered methods.
    conditional-access-policies.json Conditional Access policies.
    role-assignments.json Active directory role assignments.
    role-eligibility-schedules.json PIM eligible assignments (only with PIM).
    role-assignment-schedule-instances.json PIM active assignment instances, permanent or activated (only with PIM).
    managed-devices.json Intune-managed devices: operating system, build, compliance state.
    device-configurations.json Intune device configuration profiles (AppLocker custom profiles included) and their assignments.
    configuration-policies.json Intune settings catalog policies (App Control for Business included), their settings and assignments.
    hunting-app-control-events.json Application control event counts by device ID and action type, with the last time seen. Advanced hunting: missing when the tenant refuses it.
    hunting-app-control-blocked-files.json The 20 most-blocked files: file name, SHA-256, publisher, block and device counts.
    hunting-defender-onboarding.json Windows devices by Defender for Endpoint onboarding status, as counts.

    Unless include_identities is true, user principal names, mail addresses, people's display names and device names are replaced by sha256: and the first 16 hex characters of the SHA-256 of the lower-cased value. The same person gets the same value in every file and run, so findings can still be traced, and object IDs are kept. A hash of a known address can be confirmed by anyone who has the address, so treat the evidence as internal.

    Graph is read with paging (@odata.nextLink) and throttling handled: on 429 or 503 the collector waits as long as Retry-After says (at most five minutes) and gives up after five attempts with m365.graph_throttled.

    Problems¶

    Code Meaning
    m365.setting_missing, m365.setting_invalid A setting is missing or has a value the collector cannot use.
    m365.credentials_missing Neither client_certificate nor client_secret is set.
    m365.certificate_invalid client_certificate is not a PEM certificate followed by its private key.
    m365.auth_failed Entra ID refused the sign-in (wrong IDs, wrong or expired credential).
    m365.graph_unauthorized Graph refused the token.
    m365.graph_forbidden A permission is missing or not consented; the message names it.
    m365.graph_not_licensed The tenant lacks a licence for a required collection. PIM collections are skipped instead.
    m365.graph_throttled Graph kept throttling after five attempts.
    m365.graph_next_link_foreign Graph returned a next page on another host; it was not followed.
    m365.graph_failed, m365.graph_invalid_response Any other Graph error, or a response that is not JSON.

    The collector uses the Graph beta API for one request, the Intune settings catalog (configuration-policies.json), because it exists nowhere else. Beta APIs can change without notice. If that request starts failing, the run fails with m365.graph_failed (and the collector's health evidence shows it) until a release adapts to the change.
