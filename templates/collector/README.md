# Hound.Template.Collector

An [Evidence Hound](https://github.com/tnbozman/evidence-hound) collector for TemplateStem, type `template_type`. It was generated by `dotnet new hound-collector`. As generated, it reads `api/status` and reports one check, `template_type.healthy`. Replace that sample with the calls and checks your system needs.

## Layout

| Path | What it is |
| --- | --- |
| `src/Hound.Template.Collector/TemplateStemCollector.cs` | The collector: `Describe()` lists its checks, settings and secrets; `CollectAsync` calls TemplateStem and returns check results with evidence files. |
| `src/Hound.Template.Collector/TemplateStemCollectorServiceCollectionExtensions.cs` | `services.AddTemplateStemCollector()`, which registers it with the runner. |
| `tests/Hound.Template.Collector.Tests/TemplateStemCollectorContractTests.cs` | The shared collector contract (`EvidenceHound.Collectors.Testing`), run against recorded responses. |
| `tests/Hound.Template.Collector.Tests/TemplateStemCollectorTests.cs` | Your collector's own behaviour tests. |
| `tests/Hound.Template.Collector.Tests/recorded/` | Recorded TemplateStem responses. |

## Setup

1. Build and test it unchanged: `dotnet test`. Every test passes as generated.
2. Look up the API calls that answer your checks in TemplateStem's documentation. Choose stable, framework-neutral check IDs, such as `template_type.mfa.admins` or `template_type.backup.daily`. Never use a framework's control number.
3. Record a response for each call. Save a **synthetic** response in `recorded/`, with the shape of the real one but made-up values: fictional names, `example.com` hosts, no tokens. Never commit a real response.
4. Write a failing test in `TemplateStemCollectorTests` for each check, then make it pass in `TemplateStemCollector`. Keep the evaluation pure: turn the response into a `CheckResult` without further I/O.
5. List every check, setting and secret in `Describe()`. The runner validates config against it, and the contract fails on a check ID you did not declare.
6. Keep `TemplateStemCollectorContractTests` green. It checks that the collector:
   - describes and emits only declared checks;
   - produces evidence that can be hashed;
   - honours cancellation;
   - returns `Fail` (not throws) on a refused token;
   - never logs a secret.

   Point `Working` and `RefusedCredentials` at recorded responses for your real calls.

## Configure it

Register it in the host with `services.AddTemplateStemCollector()`, then add an instance to the deployment config:

```yaml
collectors:
  - name: example-template_type
    type: template_type
    schedule: "0 2 * * *"
    settings:
      base_url: https://template_type.example.com/   # ends in /
    secrets:
      api_token: env:HOUND_COLLECTOR_TOKEN           # a reference, never the token itself
```

Check it with `hound config validate <config>`, and list registered collectors with `hound collectors list`.

## Rules

- Expected failures (refused token, unreachable system, unexpected response) are returned as problems through `Result.Fail`. Never throw them.
- Pass the cancellation token to every call.
- Log that a secret was used, never its value.
- Fixtures and recorded responses are fictional. No real organisation names, hosts, accounts or results.
