# s09-25 evidence: onboarding a real Sophos firewall

Date: 2026-11-23. hound built from the sprint branch at `d29f894` (version 0.1.0), in the trial container (`make image`). CISO Assistant v4.3.4, the dev container's local instance. Model: Anthropic `claude-opus-5-5` through `hound onboard config`.

Setup: a home Sophos Central tenant (tenant credential, Service Principal Read-Only) managing one Sophos XGS 88w firewall and no endpoints, with one Sophos Central admin. Fictional organisation Example Pty Ltd in the trial workspace (`.dev/trial`, git-ignored). No tenant ID, host name, serial number, address, credential or supplier contact appears here.

The person ran the supplier step; Claude ran the rest at the person's request. Approvals that belong to a person (each not-applicable decision and concluding the supplier review) were recorded as "Claude (delegated by the person for the local trial)", not as the person's own.

## Result in CISO Assistant

SOPHOS-FIREWALL-ESSENTIAL-EIGHT-2023, ML1 and ML2 rows: 1 compliant (ISM-1501, with `firewalls.json` attached and the rule and run in the observation), 60 not applicable, 46 manual still to collect; the 53 ML3 rows are out of scope. A scope plan after the run is empty, so applying the scope does not undo collected results.

## Defects found

Fixed on the branch, each with a failing test first:

- `version_in` read the first digits of `XGS88w_SN01_22.0.3.576` (88) as the version, so the firmware check failed on a supported firewall (s09-11).
- A saved plan with a supplier review could not be applied: `'supplier_assessment' is not a ScopeKind` (s09-20).
- A Ctrl+V pasted into a prompt was saved in the owner's email, so CISO Assistant found no such user (s09-22).
- `hound onboard config --check` sent an empty message and got HTTP 400 (s09-21).
- Owner prompts did not say the answer must be a CISO Assistant user's email, and a name was dropped silently (s09-22).
- Maturity and trust without evidence were rejected instead of recorded as not yet assessed (s09-22).

Recorded as discovered work in the sprint file: the spec summary leaves out response fields behind `$ref`, so the model missed `firmwareVersion`; "another system" decisions are saved as not applicable, which hides the gap; environment onboarding writes rows the mapping computes; PDFs are not read by the model; `hound explain` cannot read a saved plan file and waits silently on a terminal; profile drafting does not converge; a requirement a collector marks compliant keeps status `to_do`; terminal guidance (s09-35) and ref ID prefixes (s09-34).
