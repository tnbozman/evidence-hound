# s06-10 Audit periods: open, close and sign off

**Status:** Done (2026-11-21).

## API confirmed before writing code
- From s06-05 (run [44907514706](https://github.com/tnbozman/evidence-hound/actions/runs/44907514706)): CISO Assistant v4.3.4 audits have `status` (`planned`, `in_progress`, `in_review`, `done`) and `is_locked`, but no start or end dates; `POST /api/compliance-assessments/` with `baseline` copies the baseline's results; a locked audit refuses PATCH with 400; locking an audit does not freeze the applied controls linked to it.
- So a closed period is simply locked (no "marked closed by hound" fallback was needed), and a period's dates show in its `ref_id`, its name and its ETA (the period's last day).

## What was done
- **Periods** (`AuditPeriods`, pure): an audit file's `cycle: {period, starts, close}` makes it a series. Periods follow on from `starts` (the first of a month), labelled `2026M02`, `2026Q4`, `2027H1`, `2026`, or `FY2026` for a year that does not start in January; each is its own audit `<series>-<label>`. A property test checks that every date falls in exactly one period.
- **Scope files**: `cycle` and `sign_offs: [{period, by, date}]` are read, in the JSON Schema, and validated (`scope.cycle_start_invalid`, `scope.sign_off_without_cycle`, `scope.sign_off_date_invalid`, `scope.sign_off_unknown_period`, `scope.sign_off_early`).
- **Plan and apply** expand a series on the day's date: the open period is in progress, created from the previous period as baseline, and carries the file's documents, controls, assessments and rows; an ended period moves to in review and is not written again; with `close: auto`, or once the file records its sign-off, it is set to done and locked. A missed boundary is caught up once. The writer sends `status`, `is_locked` and `baseline`; the reader reads status and lock.
- **Runs**: the config's new optional `scope:` names the scope folder. A target naming a series publishes to the period open on the run's date (`publish`, `plan`, `run`). The change-only run planner never writes an audit in review, done or locked; it reports `plan.audit_closed`.
- **Retention**: each ended period's final run (the latest complete run started by its last day) is kept for `evidence.period_retention_years` (default 7), however old.
- **`scope plan`** lists an **Audit periods** table (JSON: `periods[]`): opens (with baseline), closes (in review, awaiting sign-off), awaiting sign-off, signed off.
- `HOUND_TODAY=YYYY-MM-DD` runs any command as of another date.
- Docs: `docs/scope.md` (Audit periods section, validation codes) and `docs/configuration.md` (`scope`, `evidence.period_retention_years`).
