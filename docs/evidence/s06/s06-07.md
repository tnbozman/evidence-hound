# s06-07 Scope plan

**Status:** Done (2026-11-21).

## What was done
- Model: `ScopeObject` (kind, stable key, fields as text, and fields written on create only), `ActualObject` (with the state `hound` last wrote, from its marker), `ScopeChange`, `FieldChange`, `ScopeDrift` and `ScopePlan`.
- `ScopeDesired.From(scope)` (pure) turns the scope files into objects: a framework by URN, a domain and a system by name, a perimeter by domain and name, an audit and a control by `ref_id`, a document by its id, and a hand-written assessment by audit and requirement. Lists are sorted, so their order in a file does not matter. A control's status and reference control and a framework's library are written on create only.
- `ScopePlanner.Plan(declared, actual, prune)` (pure) returns creates, field-by-field updates, drift and, with `--prune`, deletes of managed objects only. Changes come in dependency order (frameworks, domains, perimeters, systems, audits, documents, controls, assessments) and deletes last in reverse.
- Managed objects: `hound` ends the description of each object it writes with `[hound scope <state>]`, a fingerprint of the fields it wrote (`ScopeMarker`). A managed object whose fields no longer match its marker was edited in CISO Assistant and is reported as drift; an object that exists but has no marker is taken over ("mark as managed"); objects without a marker are never deleted.
- `ScopeStateReader` reads CISO Assistant with GET requests only: the root folder and the domains under it, then each perimeter, asset, audit, evidence item and applied control in them through its `/object/` view, with IDs turned into names (users by email, frameworks by URN). Rows are read only for audits with hand-written results.
- `hound scope plan <dir> [--config] [--format markdown|json] [--prune]` validates first and reads nothing when the scope has problems. Markdown is a table for a pull request comment, with a drift table below it.
- `docs/scope.md` has a Plan section.
