# s06-01 Requirement rows by URN, scoped to the audit's groups

**Status:** Done (2026-11-21).

## What was done
- A mapping requirement is named by `urn` (one requirement node) or by `ref`. `ref` files keep working. `rows: all` (only with `ref`) writes one result to every row with that ref. Exactly one of `ref` and `urn` is required (`mapping.requirement_name_invalid`); `rows` takes only `all` (`mapping.rows_invalid`); a URN must start with `urn:` (`mapping.requirement_urn_invalid`). The JSON Schema (`schemas/mapping.schema.json`) says the same.
- Domain: `RequirementKey` (kind, value, all rows) on `RequirementMapping`, `RequirementResult` and `AuditUpdate.UpdateRequirementAssessment`. The dispatcher message uses `requirement__urn` for a URN.
- Publisher: `ICisoAssistantClient.FindRequirementAssessmentsAsync(audit, key)` returns every row for the key with its URN, ref and implementation groups, selected by `compliance_assessment__ref_id` plus `requirement__urn` or `requirement__ref_id`. `FindAuditAsync` reads the audit's selected groups from `compliance-assessments/<id>/object/` (the read serializer lists group names, the write data lists ref_ids), once per audit per publish. The pure `RequirementRows.InScope` applies CISO Assistant's rule (no selection takes everything; a row needs a selected group; a row with no groups is out).
  - A ref matching several rows without `rows: all` fails that item with `mapping.ref_ambiguous`, listing the URNs.
  - Rows outside the selected groups are left alone; the item is `skipped` with note `outside selected groups` and is not a failure. `hound publish` prints the note.
  - The old `FindRequirementAssessmentAsync` (one row by ref) is gone; `Selector.RequirementInAudit` remains for refs and `Selector.RequirementUrnInAudit` was added.
- Framework snapshots: `hound framework snapshot <library.yaml> [--out file]` writes `frameworks/<library>.json` (library and framework URN, version, groups, and each assessable node's URN, ref_id, parent, groups and a title of at most 80 characters). `FrameworkSnapshot.Resolve(key)` finds the nodes a key names.
- `hound mapping validate <file> --framework <snapshot>` also reports `mapping.urn_unknown`, `mapping.ref_unknown`, `mapping.ref_ambiguous` (with the URNs and the fix) and `mapping.framework_mismatch`, each with file and line.
- Snapshots of `essential-eight-2023` (version 3, 152 assessable rows) and `asd-essentials-enterprise-it` (version 1, 212 rows) from CISO Assistant v4.3.4 are committed under `frameworks/`, with the ASD attribution in `frameworks/README.md`. The counts match the migration plan.
- Dev seed (`dev/ciso-assistant/seed/seed.py`): imports `essential-eight-2023`, `asd-essentials-enterprise-it` and `mapping-essential-eight-2023-and-asd-essentials-enterprise-it` instead of the legacy `essential-eight`, and creates audits `EX-E8-2026` (Essential Eight 2023, groups 1 and 2) and `EX-ESSENTIALS-2026` (Essentials, group 1) beside `EXAMPLE-BASELINE-2026`.
- Docs: `docs/mapping-files.md` covers repeated requirements, `urn`, `rows: all`, group skipping, snapshots and `--framework`.
