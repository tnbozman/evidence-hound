# s06-06 Scope file and offline validation

**Status:** Done (2026-11-21).

## What was done
- Model: `EvidenceHound.Core.Scope` holds the scope as immutable records (`ScopeDocument`: setup, controls, audits), each item carrying its `SourceLine` (file and line).
- Parsing: `ScopeLoader.Parse(setup, controls, audits)` reads `scope/setup.yaml`, `scope/controls.yaml` and `scope/audits/*.yaml`. It never stops at the first problem: unknown and duplicate keys, missing keys and values of the wrong shape are all reported with their file and line. A single `perimeter` is read as a one-item list, and a requirement starting with `urn:` is read as a URN, otherwise as a ref.
- Validation: `ScopeValidator.Validate(scope, snapshots, targets)` (pure) checks duplicates, undeclared domains, perimeters, systems, frameworks, documents and controls, groups and requirements against each framework's snapshot, citations outside the audit's groups, hand-written results that a target's mapping also computes (`scope.result_conflict`), `field_visibility` below Edit for the auditor on `result`, `observation` or `evidences` (`scope.field_not_writable`), the required `unlisted` rule, and each deployment target's audit and controls (`config.target_not_in_scope`).
- CLI: `hound scope validate <dir> [--config] [--format text|json]` (exit 3 on problems) and `hound scope new-audit --framework --groups --ref-id [--out]`.
- Schema: `schemas/scope.schema.json`, checked against the example scope and the test scopes.
- Example: `examples/compliance-repo/scope/` (Example Pty Ltd, the Essential Eight ML2 audit `EX-E8-2026`).
- Docs: `docs/scope.md`.
