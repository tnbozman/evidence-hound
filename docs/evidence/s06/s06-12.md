# s06-12 Compliance repo template and guide

**Status:** Done (2026-11-21).

## What was done
- **`examples/compliance-repo/`** is now a complete, self-contained private compliance repo for the fictional Example Pty Ltd:
  - `hound.yaml`: the deployment config (CISO Assistant URL, evidence root, `scope: scope`, an M365 and two manual collectors, the Essential Eight target with its health control). Secrets are environment references only.
  - `scope/`: the setup, controls and audit files, as before, with snapshot paths inside the repo.
  - `mappings/` and `frameworks/`: copies of the repository's mappings and framework snapshots. A test keeps them identical to the originals.
  - `manual-sources/README.md`: where manual drop folders go and what never belongs in git.
  - `README.md`: the layout and the review workflow in brief.
  - `CLAUDE.md`: instructions for an AI assistant. It covers the layout, running `hound scope validate --format json` and `hound mapping validate` after every change, and never writing secrets, real evidence or results a collector computes. It adds sign-offs only when asked and uses `scope plan` as the pull request summary.
  - `.github/workflows/compliance.yml`: on every pull request it validates and posts `scope plan` as a comment. On a merge to `main` it runs `scope apply` behind the protected `ciso-assistant` environment. Actions are pinned by SHA. Plan and apply run on a self-hosted runner that can reach CISO Assistant.
- Every YAML file outside `.github/` links its JSON Schema with a `# yaml-language-server` comment.
- **`docs/scope.md`** points to the template and has a new "The review workflow" section (edit, validate, plan in the pull request, review, merge, apply, then plan again for drift). It already covered the scope file, plan, apply, drift, pruning, export, audit periods and sign-off.
- **`docs/configuration.md`** links to the template and the scope guide. It already documented `targets`.
