# s06-09 Scope apply: frameworks, audits, documents, controls and assessments

**Status:** Done (2026-11-21).

## API confirmed before writing code
- A custom library file uploads as a raw body to `POST /api/stored-libraries/upload/` (with `Content-Disposition: attachment; filename=…`) and returns 201 (s06-05, run [44907514706](https://github.com/tnbozman/evidence-hound/actions/runs/44907514706)).
- A stored library, including a mapping library, loads by URN with `POST /api/stored-libraries/{urn}/import/` (the old seed did this for all four example libraries; upstream view `StoredLibraryViewSet.import_library`).
- Found in CI while building this task: CISO Assistant v4.3.4 also loads a library when it is uploaded, and rejects a second load with "This library has already been loaded". So `hound` imports a custom library only when it was stored earlier, not right after uploading it. It also loads the Essential Eight to Essentials mapping library by itself once both frameworks are loaded, so the plan finds it loaded and writes nothing for it.

## What was done
- **Frameworks**: built-in libraries are imported by URN, custom library `file`s are uploaded, and `setup.libraries` loads other libraries (such as mapping sets) by URN. A framework loaded from an older library version than the snapshot's is reported as drift (`outdated`), not upgraded.
- **Audits**: compliance assessments by `ref_id`, in their perimeter, with framework, selected groups, ETA, due date, authors and reviewers (as actors). A rename in the file renames the audit. A locked audit and its rows are reported as drift (`locked`) and never written.
- **Documents**: evidence in the audit's domain; each file is uploaded as a revision only when no revision holds its SHA-256. A document links to the rows it cites in its audit and in every audit of the same framework sharing one of its systems. Files are relative to the compliance repo (the scope folder's parent), with globs.
- **Controls**: applied controls once each by `ref_id`, with systems and documents; status and reference control on create only. They are linked to the rows each audit cites, so a control shared by the Essential Eight and Essentials audits is one object.
- **Rows**: hand-written results; with `--config`, `unlisted` goes to in-group rows no mapping computes (rows a mapping lists as `manual_only` are not computed, so they get it too).
- **Links** are added, never removed, unless `--prune`. The scope marker's state leaves links out, so links a run adds (a collector's health evidence on a control) are neither drift nor an update.
- **Publishing** keeps the documents the scope linked to a row when it writes that row's evidence (the conflict noted in s06-08).
- **Dev seed**: `seed.py` creates only the service account, its token and the example staff users. Then `hound scope apply examples/compliance-repo/scope --config examples/example-essential-eight.yaml` writes everything else: `scripts/ca-apply-scope.sh` for `make ca-up` and the dev container, and the functional test fixture in-process. The example scope gained the Essentials and Example baseline audits, the baseline custom library file, the mapping library, `AC-AUTO-EVIDENCE`, a hand-written Essentials result and two small example PDFs.
- `docs/scope.md` and the README describe all of this.
