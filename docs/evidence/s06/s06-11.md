# s06-11 Export an existing instance

**Status:** Done (2026-11-21).

## What was done
- **`hound scope export --out <scope folder> [--root-folder Global] [--with-files]`** reads CISO Assistant (GET only) and writes `setup.yaml`, `controls.yaml`, one `audits/<ref_id>.yaml` per compliance assessment, and a snapshot of each audited framework under `frameworks/`, so the export validates offline.
- **Pure exporter** (`ScopeExport`, in `EvidenceHound.Core.Yaml`): works from the same held objects `scope plan` compares, so an export plans back to no changes by construction. Output is sorted and its scalars written one way (plain when safe, otherwise double-quoted), so a second export of an unchanged instance gives the same text.
- **Left out**: rows a run computed (run marker), rows still to do and not assessed, and evidence in the root folder, where runs put theirs. Documents and controls are listed in each audit whose rows link them, with those requirements; hand-written rows become `assessments`; `unlisted` is `not_assessed`.
- **Reader**: `IScopeExportSource.ReadAllAsync` reads every row of every audit under the root folder and builds each audited framework's snapshot from CISO Assistant (its record, its assessable requirement nodes, its loaded library's URN and version; groups from the nodes when the framework defines none). `DownloadAsync` fetches a document's latest file for `--with-files`, saved to `documents/<id>/` next to the scope folder and listed as its `files`.
- **Missing `ref_id`**: an audit, control or document without one is keyed by one made from its name (`ScopeRefIds`), by the reader and by the writer, so the plan matches it and the next `scope apply` writes the `ref_id`.
- **Marker state**: an audit's status and lock are now left out of the state `hound` records (like links), because only period audits declare them; an exported period audit then plans to no changes.
- Docs: `docs/scope.md` has an Export section.
