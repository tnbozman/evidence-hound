# s02-02 API client port and adapter

**Status:** Done (2026-11-21)

## What was done
- Port in core, `src/EvidenceHound.Core/Publishing/ICisoAssistantClient.cs`: `CheckHealthAsync`, `FindRequirementAssessmentAsync`, `UpdateRequirementAssessmentAsync`, `FindOrCreateEvidenceAsync`, `UploadEvidenceRevisionAsync` and `UpdateAppliedControlAsync`, all returning `Task<Result<T>>`. `Selector` builds the dispatcher's lookups (`ref_id`, `name`, `compliance_assessment__ref_id` + `requirement__ref_id`).
- Adapter, `src/EvidenceHound.CisoAssistant/`: a typed `HttpClient` registered by `AddCisoAssistantClient`, with `Authorization: Token <pat>`, the base URL from options, the standard resilience handler (retry with jitter on 5xx, 408 and 429, timeouts, circuit breaker; POST is never retried) and every logged header redacted.
- `ApiProblems` maps 401 and 403 to `ciso_assistant.auth`, 404 to `.not_found`, other 4xx to `.rejected` with the API's message (shortened to 500 characters), and 5xx or no connection to `.unavailable`. Several matches give `.ambiguous`.

## Deviations
- Method names carry the `Async` suffix, and problem codes are namespaced `ciso_assistant.*`.
- The evidence API has no `ref_id` filter, so the client searches with `?search=` and matches `ref_id` exactly.
