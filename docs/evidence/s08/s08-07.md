# s08-07 Terraform-style exit codes and saved plans

**Status:** Done (2026-11-22).

## What was done
- `hound scope plan --detailed-exitcode`: 0 when there is nothing to change and no drift, 2 when there is, 1 on any error (a usage error included).
- `hound scope plan --out <file>`: saves the plan (`SavedPlanFile`, format `hound-scope-plan/1`) with the changes and drift, the compliance impact, the CISO Assistant URL, the day, the scope folder and config as given, a SHA-256 over the scope files, the config and the documents' files, and for each object the plan writes or deletes a fingerprint of what it read (null for a create). No token, no document content.
- `hound scope apply <file>`: applies exactly that plan without planning again; refuses with `scope.plan_stale` (exit 3), writing nothing, when the URL differs, an input file changed, or an object it reads changed in CISO Assistant (each one named). A file that is not a saved plan is `scope.plan_invalid`.
- The example compliance repo's apply job saves the plan to `$RUNNER_TEMP` (shown in the job summary) and applies that file; its `.gitignore` ignores `plan.json`. The local trial applies its saved plan too. `docs/scope.md` has a "Saved plans" section.

## Functional check
In CI ([trial job](https://github.com/tnbozman/evidence-hound/actions/runs/44998421402/job/137134420701)) against a fresh CISO Assistant 4.3.4 seeded with the example compliance repo (`scripts/check-scope-plans.sh`, after the s08-06 edits above):

```text
$ hound scope plan $WORK/repo/scope --config examples/example-essential-eight.yaml --detailed-exitcode --out $WORK/plan.json
exit 2
0 to create, 6 to update, 0 to delete. 2 drifted.
edited assessment/EX-E8-2026/ISM-1486 in CISO Assistant
$ hound scope apply $WORK/plan.json
exit 3
is stale: CISO Assistant changed since it was made: assessment/EX-E8-2026/ISM-1486. Plan again with 'hound scope plan --out', review it, and apply that. [scope.plan_stale]
$ hound scope plan $WORK/repo/scope --config examples/example-essential-eight.yaml --out $WORK/plan.json
exit 0
$ hound scope apply $WORK/plan.json
exit 0
{'written': 6, 'failed': 0, 'skipped': 0}
```

The edit between plan and apply was made through the API (the observation of the ISM-1486 row), standing in for an edit in the UI. The script then put the example scope back with `scripts/ca-apply-scope.sh`.
