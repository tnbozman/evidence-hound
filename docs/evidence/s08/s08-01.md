# s08-01 Sophos Central access

**Status:** Done (2026-11-22).

## What was done
- New project `src/Collectors/EvidenceHound.Collectors.Sophos`.
- **Sign-in** (`SophosAuth`): a client credentials token from Sophos ID (`POST /api/v2/oauth2/token`, `scope=token`), then `GET /whoami/v1`. A tenant credential reads its own tenant from the `dataRegion` that whoami gives. A partner or organization credential needs the `tenant_id` setting (`sophos.tenant_id_required` otherwise) and finds the tenant's `apiHost` through `/partner/v1/tenants/{id}` or `/organization/v1/tenants/{id}`. A tenant credential with a different `tenant_id` set is refused (`sophos.tenant_mismatch`).
- **The token only goes to Sophos Central.** A data region that is not an `https://*.central.sophos.com` host (or the configured global API's own host, as in tests) is refused with `sophos.data_region_untrusted`.
- **Paging** (`SophosClient`): endpoints by `pageFromKey`/`nextKey` (`pageSize=500&view=full`), firewalls by page number (`pageSize=100&pageTotal=true`), with `X-Tenant-ID` and the bearer token on every request, and a cap of 1,000 pages.
- **Failures are problems, not exceptions**: `sophos.auth_failed` (names Sophos ID's error code, never the secret), `sophos.forbidden` (names the Service Principal Read-Only role), `sophos.unauthorized`, `sophos.request_failed`, `sophos.invalid_response`, `sophos.unreachable`.
- Refactor first: M365's settings reader moved into the collector abstractions as `SettingsReader(settings, prefix)`, so every collector reports `<type>.setting_missing` and `<type>.setting_invalid` the same way.
