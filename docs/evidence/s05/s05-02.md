# s05-02 Multi-factor authentication checks

**Status:** Done (2026-11-21).

## What was done
- New built-in collector `m365` (`M365Collector`), registered with `services.AddM365Collector()` from `AddBuiltInCollectors()`. It reads each Graph collection in turn, writes one minimised evidence file per collection, then evaluates every check with pure functions over the parsed `TenantData`.
- Graph collections read so far, with the application permission each needs:

  | Evidence file | Graph request | Permission |
  | --- | --- | --- |
  | `users.json` | `v1.0/users?$select=id,userPrincipalName,displayName,accountEnabled,userType,onPremisesSyncEnabled` | `User.Read.All` |
  | `mfa-registration.json` | `v1.0/reports/authenticationMethods/userRegistrationDetails` | `AuditLog.Read.All` |
  | `conditional-access-policies.json` | `v1.0/identity/conditionalAccess/policies` | `Policy.Read.All` |

- Checks (`MfaChecks`):
  - `identity.mfa.registered_all_users`: enabled member accounts (guests and disabled accounts are left out) that the registration report marks MFA-capable. `pass` at 100 %, `partial` at or above `mfa_partial_percent` (default 90), else `fail`. An account missing from the report counts as not capable. The observation gives the counts and percentage.
  - `identity.mfa.enforced_conditional_access`: an enabled policy for all users and all cloud apps that requires MFA (the `mfa` control or an authentication strength, alone or with `AND`). Its only exclusions may be the break-glass accounts named by object ID in `break_glass_accounts`; any other excluded user, group or role fails the check and is named. Report-only policies do not count.
  - `identity.legacy_auth_blocked`: an enabled policy for all users and all cloud apps that blocks both `exchangeActiveSync` and `other` client app types, with the same exclusion rule.
  - `identity.mfa.phishing_resistant_admins`: enabled policies requiring the built-in phishing-resistant authentication strength cover every privileged role (`pass`), some (`partial`, naming those not covered) or none (`fail`). A policy for all users covers every role. `privileged_roles` overrides the default 14 built-in administrator roles.
- Settings are read by `SettingsReader`, which reports every bad or missing setting at once (`m365.setting_missing`, `m365.setting_invalid`) before any request is made.
- Secrets `client_certificate` and `client_secret` are both optional to config validation; the collector fails with `m365.credentials_missing` if neither is set.
- The fictional recorded tenant (`tests/fixtures/m365/`) is `example.com`: nine users over three pages (two admins, two break-glass accounts, three staff, one disabled account, one guest), their registration details, and four Conditional Access policies. `{{graph}}` in a recording stands for the replay server's address. `RecordedTenant` replays it with WireMock.Net, and is shared with the Runtime tests (contract) through a linked source file.
