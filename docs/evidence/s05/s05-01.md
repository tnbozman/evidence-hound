# s05-01 Graph access and paging

**Status:** Done (2026-11-21).

## What was done
- New project `src/Collectors/EvidenceHound.Collectors.M365` (packable, references only the collector SDK and `Azure.Identity` 1.21.0). It calls Graph REST with `HttpClient`; there is no Graph SDK.
- `AzureIdentityCredentials` turns the app registration into a token credential:
  - `ClientCertificateCredential` when the `client_certificate` secret holds a PEM certificate and its private key (preferred);
  - `ClientSecretCredential` when only `client_secret` is set;
  - `m365.credentials_missing` when neither is set, and `m365.certificate_invalid` (a fixed message that never quotes the value) when the PEM cannot be read.
- `GraphClient.GetAllAsync` reads a whole collection:
  - a fresh bearer token from the credential on every request (Azure.Identity caches it), for the scope `<graph_url>/.default`;
  - follows `@odata.nextLink` until the last page, but only to the configured Graph host (`m365.graph_next_link_foreign` otherwise), so the token never goes elsewhere;
  - on 429 or 503 waits for `Retry-After` (seconds or a date, 10 s if absent, at most 5 minutes) and gives up after 5 attempts with `m365.graph_throttled`;
  - returns problems, never throws, for a refused token (`m365.auth_failed`), 401 (`m365.graph_unauthorized`), 403 naming the application permission the request needs (`m365.graph_forbidden`), a missing licence (`m365.graph_not_licensed`, used later for PIM), other statuses (`m365.graph_failed`) and a body that is not JSON (`m365.graph_invalid_response`).
- `Privacy.Minimise` copies items with personal data replaced by `sha256:` plus the first 16 hex characters of the SHA-256 of the lower-cased value. Hashed: `userPrincipalName`, `mail`, `otherMails`, `userDisplayName`, `emailAddress`, `deviceName`, `givenName`, `surname`, and `displayName` on objects that have a user principal name (people, not policies). Object IDs are kept. `include_identities: true` keeps everything.
- `GraphEvidence.File` writes one JSON evidence file per collection: the request, the number of pages, whether identities are hashed or included, and every item. The content is the same every run for the same data, so publishing twice uploads nothing new.
- Waiting is behind `IGraphWait`, so tests record the delay instead of sleeping.

The spec names the setting `includeIdentities`; it is `include_identities` to match every other setting key in the config.
