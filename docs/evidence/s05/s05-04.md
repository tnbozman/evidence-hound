# s05-04 Device and Office hardening checks

**Status:** Done (2026-11-21).

## What was done
- Three more Graph collections:

  | Evidence file | Graph request | Permission |
  | --- | --- | --- |
  | `managed-devices.json` | `v1.0/deviceManagement/managedDevices?$select=id,deviceName,operatingSystem,osVersion,complianceState,userPrincipalName` | `DeviceManagementManagedDevices.Read.All` |
  | `device-configurations.json` | `v1.0/deviceManagement/deviceConfigurations?$expand=assignments` | `DeviceManagementConfiguration.Read.All` |
  | `configuration-policies.json` | `beta/deviceManagement/configurationPolicies?$expand=settings,assignments` | `DeviceManagementConfiguration.Read.All` |

  Settings catalog policies, where Intune keeps the Office macro and attack surface reduction settings, exist only in the Graph **beta** API. This is the collector's one beta call; the sprint plan says v1.0, so it is noted under Discovered work. Device names and their users are hashed in `managed-devices.json` like every other identity.
- Checks:
  - `endpoint.managed.compliant_ratio` (`DeviceChecks`): the share of Intune-managed Windows devices whose compliance state is `compliant`. `pass` at `compliant_pass_percent` (default 95), `partial` at `compliant_partial_percent` (default 80), else `fail`; no managed Windows devices fails.
  - `endpoint.os.supported_versions`: every managed Windows device's build (the first three parts of its OS version) is in `supported_windows_builds`, a required setting so the list is kept current by the operator rather than going stale in code. A failure lists the unsupported builds with their counts.
  - `apps.office.macros_blocked_from_internet` (`OfficeChecks`): an assigned settings catalog policy enables "Block macros from running in Office files from the Internet" for Word, Excel and PowerPoint. `pass` when all three are assigned to all users; `partial` when only some apps are, or only through group assignments; else `fail`.
  - `endpoint.asr.office_rules_enabled`: the four Office attack surface reduction rules (child processes, executable content, code injection, Win32 API calls from macros) in block mode in an assigned policy, read from settings catalog policies and from legacy endpoint protection profiles. `pass` when all four block; `partial` when some block or are in audit or warn mode, naming those not blocking; `fail` when none is configured.
- `IntunePolicy` reduces both kinds of policy to name, assignment (all users, all devices, any) and key and value pairs. Settings catalog values are found at any depth, so grouped settings such as the ASR rules are read the same way as single ones.
- New options are validated: the partial percentage may not exceed the pass percentage, and every supported build must look like `10.0.26100`.
