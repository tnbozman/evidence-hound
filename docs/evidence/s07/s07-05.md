# s07-05 CISO Assistant settings as configuration

**Status:** Done (2026-11-22).

## What was done
- **`scope/settings.yaml`**: `feature_flags` (each `true` or `false`) and `general` settings (any JSON value), by name. Only the named settings change.
- **Settings snapshot** `src/EvidenceHound.Core/Scope/ciso-assistant-settings.json` for v4.3.4 has the 62 flags the pinned stack's API offers, with their defaults, plus the 2 gated flags (`chat_mode` needs `ENABLE_CHAT`, `infra_config_management` needs `ENABLE_INFRA_CONFIG_MANAGEMENT`), 47 general settings, and `openai_api_key` as a secret. It is embedded, so validation works offline. The JSON schema lists the same names, and a test keeps the two in step.
- **Validation**: `settings.flag_gated` for a gated flag, `settings.flag_unknown` and `settings.setting_unknown` (the hint lists the valid names). A secret setting is `scope.secret_in_file`. `settings.feature_disabled_in_use` covers `compliance: false` while the scope declares audits. The sprint's `tprm: false` example waits for third-party files (s10), so no scope file uses `tprm` yet.
- **Writes**: the feature-flags endpoint validates the whole body and resets any missing flag to its default, so hound PUTs every flag as held, with the one change. General settings are written with PATCH, which keeps the keys it leaves out.
- **`scope plan --show-unmanaged`** adds an "Unmanaged settings" section: every flag and setting the file does not name, with its current value.
- The example compliance repo turns on `enforce_mfa` (Essential Eight MFA) and `tprm`, and turns off `dora` and `nis2`.
