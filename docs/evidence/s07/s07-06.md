# s07-06 Tutorial: your private compliance repo and first deployment

**Status:** Done (2026-11-22). A reviewer still has to follow it on a fresh VM.

## What was done
- **[`docs/tutorials/first-deployment.md`](../../tutorials/first-deployment.md)** covers seven steps with Example Pty Ltd:
  1. Create the private repo from the template, with branch protection, required review, secret scanning with push protection, and the `ciso-assistant` environment.
  2. What goes in the repo and what never does.
  3. Install the stack: secrets files, both checkouts, `deploy.env` linked as the stack's `.env`, `./manage.sh createsuperuser`, and `runner-token.sh`.
  4. Register the Microsoft 365 app, and store its certificate as the `m365_client_certificate` secret.
  5. Validate, plan and apply, first setup, settings (with `enforce_mfa`) and access, then the Essential Eight audit.
  6. Start the schedule and check it with `hound status`.
  7. Day-2 changes, all as pull requests.
- **Template repo** (`examples/compliance-repo`) gains:
  - `deploy/deploy.env`: the stack's non-secret settings. It sets `COMPOSE_FILE` to include the repo's override, so the stack's own scripts pick it up too.
  - `deploy/compose.override.yml` and `deploy/README.md`.
  - A `.gitignore` for secrets, keys, certificates, `.env` files and evidence.
  - A `secrets` job in its workflow (gitleaks, full history) that `validate` waits for.
  - `scope/access.yaml` and `scope/settings.yaml` came with s07-04 and s07-05.
