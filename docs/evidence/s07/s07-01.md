# s07-01 Collector runner image

**Status:** Done (2026-11-21).

## What was done
- **Dockerfile** `src/EvidenceHound.Cli/Dockerfile` (where Dependabot's `docker` entry already looked). Multi-stage: the SDK stage (pinned by digest) restores in locked mode and publishes framework-dependent for one runtime identifier; the runtime stage is `mcr.microsoft.com/dotnet/runtime:10.0-noble-chiseled` (pinned by digest): no shell, no package manager, non-root user `app` (1654), entrypoint `/app/hound`. The public `frameworks/` and `mappings/` are copied to `/app/frameworks` and `/app/mappings`.
- **One architecture per image.** `EvidenceHound.Cli.csproj` declares `RuntimeIdentifiers` `linux-x64;linux-arm64` (lock file updated), so the image carries only its own native libraries (Kafka, Azure identity): 201 MB instead of 305 MB. The SDK stage runs on the build platform (`--platform=$BUILDPLATFORM`) and cross-publishes, so arm64 builds need no emulation.
- `global.json` is left out of the image build: it pins the dev SDK band (10.0.1xx), and the build uses the pinned SDK image instead.
- `.dockerignore` keeps build output, `.git`, `.dev`, evidence and env files out of the build context.
- **CI** (`ci.yml`, job `image`): `make test-image` builds the image and runs `tests/image/runner-image.bats`, then Grype (`anchore/scan-action`; the sprint allows Trivy or Grype) fails the job on any high or critical finding.
- **Publishing** (`.github/workflows/runner-image.yml`): on push to main, a `v*` tag or by hand. Builds and tests the candidate, scans it, then builds `linux/amd64` and `linux/arm64`, pushes to `ghcr.io/<owner>/<repo>` (`dev` from main; `X.Y.Z` and `X.Y` from a tag) with BuildKit provenance (`mode=max`) and an SBOM, and adds a GitHub build provenance attestation (`actions/attest-build-provenance`).
- `make image` and `make test-image` (variable `HOUND_IMAGE`, default `evidence-hound-runner:test`).
