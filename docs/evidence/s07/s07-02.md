# s07-02 Compose stack

**Status:** Done (2026-11-22). The fresh-VM check is for a reviewer to repeat (see below).

## What was done
- **`deploy/compose/compose.yml`**: CISO Assistant backend, worker and frontend pinned to one release (`CA_VERSION`, v4.3.4), PostgreSQL 16, Caddy with `tls internal`, and the collector runner. Three networks: `web` (Caddy is the only published port), `data` (internal, PostgreSQL with the backend and worker), `collect` (the runner and the backend only, plus outbound internet). The runner is read-only, drops every capability, has `no-new-privileges` and publishes no port.
- **Secrets** are Docker secrets files in `HOUND_SECRETS_DIR`, never variables. PostgreSQL reads `POSTGRES_PASSWORD_FILE`. CISO Assistant can only read its database password and secret key from variables, so `ca-env.sh` (mounted read-only) exports them from the files inside the backend and worker. `manage.sh` runs management commands the same way (`./manage.sh createsuperuser`). The runner understands Docker's `_FILE` convention for any variable (`HOUND_CA_TOKEN_FILE`).
- **`runner-token.sh`** creates the runner's service account and writes its token straight into the secrets folder.
- **Kafka profile**: Redpanda and CISO Assistant's dispatcher, built from the same release.
- **`.env.example`** documents every variable (now including `COMPOSE_FILE` for a private repo's override). The real `.env` and the secrets folder are git-ignored.
- **Runner image time zones**: the chiseled runtime has no time zone database, so the scheduler could not resolve `Australia/Sydney` (`config.time_zone_unknown` in the smoke test). The Dockerfile copies `/usr/share/zoneinfo` from the SDK stage, which is the same Ubuntu release.
