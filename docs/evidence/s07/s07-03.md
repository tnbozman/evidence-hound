**Status:** Done (2026-11-22), except the overnight run, which the person is doing.

## What was done
- **`hound serve --config <file>`** runs each collector on its cron `schedule` (Cronos) in `scheduler.time_zone` until stopped. Each collector gets a steady jitter of up to `jitter_seconds`. One collector never has two runs at once: an occurrence that falls due while the last run is still going is skipped with a warning. Runs that were missed while the host was down run once, late. SIGTERM cancels the current run and exits 0.
- Each scheduled run is `hound run --only <name>`, which reads the config again, so pulling the compliance repo changes the next run.
- The runner container runs `hound serve` by default (`restart: unless-stopped`). `docs/running.md` documents host cron and a systemd timer as the alternative.
- The example config (`examples/compliance-repo/hound.yaml`) runs the Microsoft 365 collector nightly at 03:00 Sydney time, publishing to `EX-E8-2026`. Its certificate is `file:/run/secrets/m365_client_certificate`.
