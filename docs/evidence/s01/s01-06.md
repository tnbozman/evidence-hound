# s01-06 Global exception handler and logger

**Status:** Done (2026-11-21). Added to the sprint at the maintainer's request.

## What was done
- `HoundCli.RunAsync` builds one host per run with one logger provider, `StderrLoggerProvider`, which writes `level: message` to stderr. Stdout carries only command output. The level comes from standard configuration (`Logging__LogLevel__Default`).
- Global handler in the composition root: an unexpected exception from any command is logged at `Critical` with a one-line summary (`InvalidOperationException: ...`) and exits 1; the full exception is logged at `Debug`. Cancellation logs `warn: Cancelled.` and exits 130. System.CommandLine's own exception handler is turned off so there is one path.
- `Log.cs` holds every CLI log message (`[LoggerMessage]`, fixed event IDs). `Log.Problems` logs each expected failure at `Error` with `Code` and `Message` as structured state and returns exit code 3. Parse and usage errors go through `Log.Usage`.
- `collect`, `mapping validate`, `mapping apply` and `plan` all report through it. Config loading now returns `Result<HoundConfig>` with problem codes (`config.file_not_found`, `config.yaml_invalid`), replacing the ad hoc `ConfigLoad` type. `collect` moved into its own `CollectCommand`.
- The core is unchanged: it still returns `Result`s and never throws for expected failures.
- Docs: "Errors and logging" in [`docs/engineering.md`](../../engineering.md).
