# s01-04 Mapping engine

**Status:** Done (2026-11-21)

## What was done
- `MappingEngine.ApplyMapping(FrameworkMapping, IReadOnlyList<CheckResult>) -> IReadOnlyList<RequirementResult>` in `src/EvidenceHound.Core/Mapping/`. Pure: no clock, no I/O.
- `RequirementResult(RequirementRef, Result, Observation, EvidenceRefs)` with `ComplianceResult` `Compliant`, `PartiallyCompliant`, `NonCompliant`, `NotAssessed` and `NotApplicable`.
- Rules: missing or `Error` check gives `NotAssessed`; `NotApplicable` checks are ignored unless all are; `AllPass` is compliant only if every applicable check passed and non-compliant on any failure; `AnyPass` mixed gives `PartiallyCompliant`; `Threshold(n)` counts passes against n, capped at the number of applicable checks.
- Latest result per check wins (ties broken by source, outcome, observation and evidence so the output never depends on input order). Output is in mapping file order; evidence refs are the sorted distinct union.
- `MappingRule` records carry their own `Name` and `Assess(OutcomeTally)`, so a new rule is a new record and the engine does not change.
- CLI: `hound mapping apply <mapping> <checks.json>` reads a check results file (`CheckResultsJson`, every problem names the file and entry) and prints a table. Fixture: `tests/fixtures/checks-sample.json` (fictional).
- Docs: "How results are worked out" in [`docs/mapping-files.md`](../../mapping-files.md).

**Deviation from the plan:** the plan lists four requirement results, but also says a requirement whose checks are all not applicable is not ignored. `NotApplicable` was added for that case; it matches CISO Assistant's `not_applicable` requirement result. Recorded under "Discovered work".
