# s01-01 Result type

**Status:** Done (2026-11-21)

## What was done
- `src/EvidenceHound.Core/Results/Result.cs`: `Result<T>` is a closed record hierarchy, `Result<T>.Ok(Value)` or `Result<T>.Fail(Errors)`, with `Map`, `Bind` and `Match`. `Result.Combine` turns a list of results into a result of a list and collects every error.
- `src/EvidenceHound.Core/Results/Problem.cs`: the error record with `Code` and `Message`.
- Immutable (get-only properties), `T : notnull`, null values and empty error lists rejected. `Fail` compares its errors by sequence, so two failures with the same errors are equal.
- `FsCheck.Xunit.v3` 3.6.0 added to the core test project only. The core still has no package references.

**Deviation from the plan:** the plan names the error record `Error`. Analyser rule CA1716 rejects that name (it is a reserved word in Visual Basic), and CLAUDE.md forbids weakening analyser rules, so the record is called `Problem`. Recorded under "Discovered work" in the sprint file.
