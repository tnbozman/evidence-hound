# s01-03 Framework mapping model and loader

**Status:** Done (2026-11-21)

## What was done
- Core (`src/EvidenceHound.Core/Mapping/`, no packages): `FrameworkMapping` (`FrameworkUrn`, `Requirements`), `RequirementMapping` (`RequirementRef`, `Checks`, `Rule`) and the closed `MappingRule` set `AllPass`, `AnyPass`, `Threshold(n)`. `Create` functions reject a non-URN framework, duplicate requirement refs, a requirement with no checks or a repeated check, and a threshold outside 1 to the number of checks.
- Adapter `src/EvidenceHound.Core.Yaml` (YamlDotNet, keeps the core dependency-free): `MappingLoader.Parse(yaml, source, knownChecks?)` returns `Result<LoadedMapping>`. Every problem starts with `<file> line <n>:` and all problems are reported at once. Unknown check IDs are allowed and come back as warnings when a set of known checks is supplied.
- `schemas/mapping.schema.json` (JSON Schema 2020-12) and the fictional `mappings/example.yaml` (4 requirements, all three rules).
- CLI: `hound mapping validate <file>` prints `valid: N requirements` (exit 0) or each problem (exit 3).
- Docs: [`docs/mapping-files.md`](../../mapping-files.md).
