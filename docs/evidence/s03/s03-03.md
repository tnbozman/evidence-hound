# s03-03 Evidence store and manifest

**Status:** Done (2026-11-21).

## What was done
- Core `Packaging`: `CollectedFile`, `ManifestEntry`, `EvidenceManifest`, the pure `Manifests.Build` (sorted entries with size and SHA-256; rejects paths, duplicate names and names starting with `_`) and `Manifests.ToJson` (deterministic snake_case JSON).
- Pure `Retention.RunsToDelete(runs, now, days)`: older than the limit, except the latest complete run, which is always kept.
- Port `IEvidenceStore` and the thin `FileEvidenceStore`: `<root>/<collector>/<yyyyMMddTHHmmssfffZ>/` with the files, then `_manifest.json` last, so a folder without a manifest is an incomplete run. It refuses a collector name that is not a plain folder name and a second run at the same millisecond.
- Core ports `ICollector` (with `Version` for the manifest) and `IClock`. The built-in `fake` collector reports four checks that match `mappings/example.yaml`, one JSON file per check (no timestamps inside, so re-publishing uploads nothing new) and two control statuses.
- `CollectStep`: resolve the instance's secrets, collect, build the manifest, store, apply retention. A missing secret or a failed collection stores nothing.
- `hound collect --config <file>` now collects every configured collector into the store and exits 1 if any failed; `--dry-run` still only reports the count. `Result.BindAsync` keeps the I/O pipeline flat.

## Deviations
- The functional check uses `hound collect` (no publishing) rather than a dry run: `--dry-run` on `collect` means "contact nothing". `hound run --dry-run` (s03-04) collects and stores evidence but sends nothing.
- `collected_at` in the manifest keeps the clock's full precision; the folder name is to the millisecond.
