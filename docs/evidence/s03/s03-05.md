# s03-05 Run status and collector health

**Status:** Done (2026-11-21).

## What was done
- `RunRecord` (start, end, outcome, checks passed, failed and other, problems, publish counts) is built by the pure `RunRecords.Summarise` after every run and saved by `FileRunRecordStore` to `<evidence root>/_status/<collector>.json` as snake_case JSON.
- The pure `Health.Plan` turns a record into "collector health" evidence: file `collector-health-<collector>.json`, ID `hound-health/<collector>`, linked to `target.health_control`. The runner uploads it after each run (planned only under `--dry-run`); a failed health upload marks the collector failed.
- `UploadEvidence` gained `AppliedControlRefIds`. The publisher links the evidence to each control after a sent or skipped upload, and the REST client adds it to the control's `evidences` only if it is missing. The Kafka transport uploads but does not link, because the dispatcher cannot.
- `hound status --config <file>` prints the latest run per collector from the local store; a configured collector with no record shows "never run".
- The seed adds the fictional applied control `AC-AUTO-EVIDENCE` ("Automated evidence collection"), and the example config points `health_control` at it.
