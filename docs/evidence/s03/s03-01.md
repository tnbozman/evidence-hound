# s03-01 Deployment configuration

**Status:** Done (2026-11-21).

## What was done
- New project `src/EvidenceHound.Runtime` with `DeploymentConfig` (CISO Assistant connection, evidence root and retention, collector instances, target) and `ConfigLoader`, which parses YAML with line numbers and collects every problem instead of stopping at the first.
- `SecretReference` in the core: `env:NAME` or `file:/absolute/path`. Parse problems never echo the text.
- Inline secrets are rejected: a token or `secrets` entry that is not a reference, a setting named like a secret, a setting holding a private key, or a run of 32 or more letters and digits.
- Unknown collector types list the known ones; collector names must be unique and safe as folder names; schedules must be five-field cron; unknown keys are errors.
- `schemas/config.schema.json` and `docs/configuration.md`. `examples/example-pty-ltd.yaml` is complete and fictional, with one `fake` collector.
- `hound config validate <file>` prints `valid` or logs every problem and exits 3. `collect` and `plan` now load config through the same loader; the s00 `ConfigFile`/`HoundConfig` are gone.

## Deviations
- The config keeps the single `target` from s01 (mapping, `compliance_assessment`, `controls`). Per-check control refs were not needed: control statuses already name a control key.
- The only known collector type is `fake`; the SDK in s04 adds registration.
