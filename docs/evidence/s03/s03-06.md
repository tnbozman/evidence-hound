# s03-06 Dev container with CISO Assistant on one network

**Status:** Done in code (2026-11-21); the rebuild check below is for a developer to run, because this cloud box cannot run the dev container.

Added during the sprint at the product owner's request: "it would be good for CISO Assistant to be deployed in the same docker network enabling development against CISO Assistant".

## What was done
- `.devcontainer/compose.yml` defines the dev container as the `dev` service and includes `dev/ciso-assistant/compose.yml` (backend, frontend, Caddy), so every service shares the compose project's `default` network. Redpanda and the dispatcher stay behind the `kafka` profile.
- A one-shot `ca-seed` service extends the backend (no ports, no restart, no health check), waits for `service_healthy`, runs `seed.sh` against `http://backend:8000/api`, and pipes the output through the new `write-env.sh`. That script prints every line except the token and writes `HOUND_CA_URL=http://backend:8000/api/` plus the token to the `hound-ca-env` volume (mode 644 there, so the dev user can read it).
- `scripts/dev-ca-env.sh` (the `postStartCommand`) waits up to 600 seconds for that file and copies it to `.dev/ca.env` with mode 600. If CISO Assistant is not ready, the dev container still starts and prints how to retry.
- `.devcontainer/initialize.sh` (the `initializeCommand`, on the host) writes the Django secret key from `scripts/ca-secret-key.sh` to the git-ignored `.devcontainer/.env`, which compose reads for the included file. Compose refuses to start without it.
- Docker-in-docker stays, so Testcontainers and `make ca-up` work inside the dev container as before. `scripts/ca-seed.sh` now uses `write-env.sh` too.

## Rebuild check (run by a developer)
1. Pull the branch on your machine, then in VS Code run **Dev Containers: Rebuild Container**. The first build pulls the CISO Assistant images and waits for the backend (up to about 3 minutes).
2. In the dev container terminal, check the seed: `cat .dev/ca.env | cut -c1-25` shows `HOUND_CA_URL=http://backe` and `HOUND_CA_TOKEN=...`.
3. Check the network: `curl -s http://backend:8000/api/health/` returns a JSON body.
4. Publish the example run: `set -a && . .dev/ca.env && set +a && make run ARGS="run --config examples/example-pty-ltd.yaml"` exits 0 with `"outcome": "succeeded"`.
5. Open <https://localhost:8443> on your machine, sign in as `admin@example.com` (`change-me-local-only` unless you set `HOUND_CA_ADMIN_PASSWORD`) and open the "Example baseline 2026" audit.

If step 2 says CISO Assistant was not seeded, run `docker compose -f .devcontainer/compose.yml logs ca-seed` on the host.
