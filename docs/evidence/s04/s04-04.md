# s04-04 Manual-upload collector

**Status:** Done (2026-11-21).

## What was done
- New built-in collector `manual` (`src/Collectors/EvidenceHound.Collectors.Manual`). Each collector instance is one manual source, with settings `drop_folder`, `patterns`, `checks`, `due_days` and `owner`.
- Each run emits every accepted file dated within the due interval as evidence. The same content dropped twice is emitted once, under its newest name. The newest file decides each check:
  - an attested outcome becomes the check's result, naming who attested, when, and the note;
  - a file with no attestation, or none for that check, gives `partial` ("evidence present, not attested");
  - a source with no file in the interval gives `error` ("overdue since <date>", or "no evidence uploaded yet").
- The attestation sidecar is `<file>.attest.yaml`, holding who, date, a note and an outcome per check. It is also stored as evidence. A UTF-8 byte-order mark (as Notepad writes) is accepted.
- The decision logic (`ManualAssessment`) is pure. The collector only reads the folder.
- `hound manual upload --config <file> --source <name> <file>`:
  - checks the file against the source's patterns;
  - skips content already in the drop folder;
  - prompts on stderr for an attestation (who, defaulting to the owner; an outcome per check, defaulting to pass; a note);
  - copies the file and writes the sidecar.
- SDK changes the manual collector needed:
  - `CollectorDescription.ChecksSetting` names a setting that lists the check IDs per instance. The contract kit and `hound collectors list` accept it.
  - `SettingDescription.IsPath` marks a setting as a path, and the config loader resolves it against the config file's folder.
  - `hound` reads prompts from an input reader: `Console.In` in `Program`, empty in tests that do not answer.
- The fictional example baseline and mapping gain requirement EX-4.1 (`all_pass` of `network.firewall.rules_reviewed` and `network.firewall.config_exported`). Five CLI and functional tests assert counts and rows from the example mapping; their expected values now include EX-4.1 (for example 9 → 10 planned updates). No assertion was loosened.
- The fictional export is `examples/manual-exports/example-firewall-config-export.txt`. `manual/` folders stay git-ignored so real drop folders are never committed.
- `docs/configuration.md` has a Manual sources section; the contract kit README covers `ChecksSetting`.
