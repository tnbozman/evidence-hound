# s04-01 Collector interface

**Status:** Done (2026-11-21).

## What was done
- New project `src/EvidenceHound.Collectors.Abstractions` (packable, references only Core). `ICollector` moved here from Core with `Type`, `Version`, `Describe()` and `CollectAsync(CollectorContext, CancellationToken) -> Task<Result<CollectionResult>>`.
- `CollectorDescription` lists the check IDs a collector can report and its settings and secrets (`SettingDescription`: name, description, required).
- `CollectorContext` carries only the instance name, typed `CollectorSettings`, resolved secrets, `IClock`, an `ILogger` and an `IHttpClientFactory`.
- `CollectionResult` holds check results, `CollectedEvidence` files (file name, media type, a stream to read) and control statuses. `CollectStep` reads each stream once and hashes the content into the manifest as before.
- `services.AddCollector<T>()` registers a collector. The CLI registers the built-ins with `AddBuiltInCollectors()`, then builds a `CollectorRegistry` from every `ICollector` in DI at startup. If two collectors share a type, the CLI stops with `collector.type_duplicate` and exits 3.
- Config validation uses what each type describes: a missing required setting or secret is reported as `config.setting_missing` or `config.secret_missing`, with its file and line.
- `hound collectors list` prints each registered type with its version, check IDs, settings and secrets.
