# s04-03 Collector template

**Status:** Done (2026-11-21).

## What was done
- `templates/collector` is a `dotnet new` template, short name `hound-collector`. `-n Example.Widget` generates a self-contained solution:
  - `src/Example.Widget/WidgetCollector.cs`: a sample collector of type `widget`. It reads the `base_url` setting and the `api_token` secret, calls `api/status`, and reports `widget.healthy` with the response as evidence. A refused token, an error status, no answer or a malformed response each return a problem; none throws.
  - `AddWidgetCollector()`, to register the collector.
  - `tests/Example.Widget.Tests`: the contract kit applied against recorded responses, and two behaviour tests.
  - `recorded/status.json`, a synthetic sample response.
  - A README with layout, setup steps, config example and rules.
- The generated solution brings its own `Directory.Build.props`, `Directory.Packages.props` and `global.json`, so it builds the same inside this repo or anywhere else. `--HoundVersion` sets the SDK package version (default `0.1.0`).
- Template tokens: `Hound.Template.Collector` becomes the name, `TemplateStem` the name's last segment (class names), `template_type` that segment in lowercase (collector type and check ID prefix), and `0.0.0-hound` the SDK version.
- `EvidenceHound.Core` is now an explicit package, because the Abstractions package depends on it. The template test found this: restoring a generated collector failed with `NU1101: Unable to find package EvidenceHound.Core`.
- `scripts/test-template.sh` (`make test-template`, CI job `template`):
  1. packs Core, Abstractions and Testing with a unique version into a temporary feed;
  2. installs the template into a throwaway template store, leaving the user's untouched;
  3. generates `Example.Widget` in a temp folder, then restores, builds and tests it.
- `CONTRIBUTING.md` explains how to use the template.
