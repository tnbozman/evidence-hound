**Goal:** the same collectors and evidence produce CMMC Level 2 (NIST SP 800-171 Rev 2) results, with no collector changes, and the SSP generator from s11 gains the NIST SP 800-171 / CMMC Level 2 layout and its POA&M rules.

### s17-01 CMMC Level 2 mapping file
- [ ] Done

**Story:** As a compliance owner pursuing CMMC, I want existing checks mapped to NIST SP 800-171, so that one evidence stream serves both frameworks.

**Acceptance criteria**
- `mappings/cmmc-2.0.yaml` targets CISO Assistant's built-in `cmmc-2.0` framework (`urn:intuitem:risk:framework:cmmc-2.0`, library version 6 in v4.3.4) at group `L2`: 110 practices, the requirements of NIST SP 800-171 Rev 2 that CMMC Level 2 assesses. A Rev 3 mapping to the built-in `nist-800-171-rev3` library is optional (person's decision, Nov 2026).
- Where CISO Assistant ships a mapping library between relevant frameworks, it is used to seed the file; otherwise the mapping is built with its `prepare_mapping_v2.py` tool and reviewed.
- Requirements outside the reach of collectors (physical protection, personnel security, media protection and similar) are listed as `manual_only` with suggested manual sources.

**Tests first**
- `CmmcMappingTests.All_requirement_refs_exist_in_library_snapshot`
- `CmmcMappingTests.No_collector_changes_needed` (all mapped check IDs already exist)

**Functional check**
- One `hound run` updates the Essential Eight, Essentials and CMMC Level 2 example audits.

### s17-03 NIST SP 800-171 and CMMC Level 2 profile
- [ ] Done

Builds on the SSP engine, gaps, POA&M and versions from s11-02 to s11-05.

**Story:** As a defence supplier preparing for CMMC Level 2, I want an SSP and POA&M in the shape assessors expect for NIST SP 800-171, so that the plan is ready for an assessment.

**Acceptance criteria**
- The `nist-800-171` profile lays out: system identification and owners; the system environment and boundary (the declared sections and diagrams); the asset inventory with CMMC asset categories (CUI, security protection, contractor risk managed, specialised, out of scope) from an asset custom field (s11-12); external service providers from suppliers and solutions; then every requirement grouped by family with status, statement, responsible party and evidence; then the POA&M.
- It works with CISO Assistant's `cmmc-2.0` library at group `L2`, and with the optional Rev 3 mapping (s17-01).
- Requirements CMMC does not allow on a POA&M are flagged in the POA&M and in the gaps, from a list kept in the profile with its source cited.

**Tests first**
- `Nist171SspTests.Groups_requirements_by_family`
- `Nist171SspTests.Asset_categories_come_from_custom_field`
- `Nist171SspTests.Renders_expected_markdown_from_fixture` (golden file)

**Functional check**
- Generate the SSP and POA&M for the fictional Example Pty Ltd CMMC Level 2 audit on the local stack and read them against the profile's section list.
