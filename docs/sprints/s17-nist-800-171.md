### s17-01 CMMC Level 2 mapping file
- [ ] Done

**Story:** As a compliance owner pursuing CMMC, I want existing checks mapped to NIST SP 800-171, so that one evidence stream serves both frameworks.

**Acceptance criteria**
- `mappings/cmmc-2.0.yaml` targets CISO Assistant's built-in `cmmc-2.0` framework (`urn:intuitem:risk:framework:cmmc-2.0`, library version 6 in v4.3.4) at group `L2`: 110 practices, the requirements of NIST SP 800-171 Rev 2 that CMMC Level 2 assesses. A Rev 3 mapping to the built-in `nist-800-171-rev3` library is optional (person's decision, Nov 2026).
- Where CISO Assistant ships a mapping library between relevant frameworks, it is used to seed the file; otherwise the mapping is built with its `prepare_mapping_v2.py` tool and reviewed.
- Requirements outside the reach of collectors (physical protection, personnel security, media protection and similar) are listed as `manual_only` with suggested manual sources.

**Tests first**
- `CmmcMappingTests.All_requirement_refs_exist_in_library_snapshot`
- `CmmcMappingTests.No_collector_changes_needed` (all mapped check IDs already exist)

**Functional check**
- One `hound run` updates the Essential Eight, Essentials and CMMC Level 2 example audits.

**Notes**
- CISO Assistant v4.3.4's `cmmc-2.0` library (version 6) tags its 17 Level 1 practices `L1` only and the other 93 `L2`, so the Level 2
  audit selects both groups (`groups: [L1, L2]`); an audit at `L2` alone would leave out the Level 1 practices. Snapshot:
  `frameworks/cmmc-2.0.json`.
- CISO Assistant ships no mapping library between the Essential Eight and CMMC, so the mapping is drafted from
  `mappings/essential-eight-2023.yaml` through the s12-08 crosswalk to 800-171 (each practice takes the checks of the Essential Eight
  requirements linked to it), then reviewed: ASD incident reporting is left out of IR.L2-3.6.2 (DoD reporting is s17-07), and
  RA.L2-3.11.1 also takes `risk.studies_reviewed`. 32 practices have checks; 78 are `manual_only` with the record each family keeps.
- New mapping key `covers: part` (schema, loader, engine, `docs/mapping-files.md`): when every check passes, the row is partially
  compliant, not compliant, and its observation says a person must assess the rest. Every CMMC row uses it: Essential Eight evidence
  from Microsoft 365, Sophos Central and the scanner covers only part of a practice that applies to every system holding CUI, and
  publishing it as compliant would overstate the SPRS position. `CmmcMappingTests` allows a whole row only where the crosswalk has an
  equal or superset link.
- The example compliance repo gains the `EX-CMMC-2026` audit and its target; `TwoAuditsFunctionalTests` checks one run fills it.

### s17-03 NIST SP 800-171 controls annex and CMMC Level 2
- [ ] Done

Builds on the SSP engine, gaps, POA&M and versions from s11-02 to s11-05.

**Story:** As a defence supplier preparing for CMMC Level 2, I want the SSP's controls annex and POA&M in the shape assessors expect for NIST SP 800-171, so that the plan is ready for an assessment.

**Acceptance criteria**
- One layout (maintainer, 2026-11-24): the plan already follows NIST SP 800-18 Rev 1 Appendix A (s11-04). This task adds the `nist-800-171` controls annex and the CMMC specifics to that layout, not a second layout: the asset inventory in the system environment section carries CMMC asset categories (CUI, security protection, contractor risk managed, specialised, out of scope) from an asset custom field (s11-12); the annex lists every requirement grouped by family with status, statement, responsible party, evidence and its POA&M item; the POA&M follows.
- It works with CISO Assistant's `cmmc-2.0` library at group `L2`, and with the optional Rev 3 mapping (s17-01).
- Requirements CMMC does not allow on a POA&M are flagged in the POA&M and in the gaps, from a list kept in the profile with its source cited.

**Tests first**
- `Nist171SspTests.Groups_requirements_by_family`
- `Nist171SspTests.Asset_categories_come_from_custom_field`
- `Nist171SspTests.Renders_expected_markdown_from_fixture` (golden file)

**Functional check**
- Generate the SSP and POA&M for the fictional Example Pty Ltd CMMC Level 2 audit on the local stack and read them against the profile's section list.

**Notes**
- `SspAnnex` gives each row its `Family` ("Access control (AC)", from the snapshot's parent names); `SspLayout` with profile
  `nist-800-171` writes the annex as one table per family (Requirement, Title, Level, Status, Statement, Responsible, Evidence, POA&M) and
  cites NIST SP 800-171 3.12.4 instead of ISM-0041. Golden file `ssp-nist-800-171.md`.
- Asset categories: CISO Assistant's asset custom fields are an Enterprise feature, so the category is the system tag
  `cmmc_asset_category` (cui, security_protection, contractor_risk_managed, specialized, out_of_scope; 32 CFR 170.19(c)(1), Table 1),
  checked by `SspValidator` (`ssp.asset_category_invalid`) and the scope schema. The test keeps the planned name
  `Asset_categories_come_from_custom_field`; `SspBuilderTests.Cmmc_asset_category_comes_from_the_system_tag` covers the read. An
  untagged system is a gap.
- POA&M rules: `CmmcPoam` (32 CFR 170.21(a)(2)): only 1-point requirements by the bundled SPRS methodology, SC.L2-3.13.11 named for a
  person, never 3.1.20, 3.1.22, 3.10.3-5 or 3.12.4. Flagged in the gaps, the annex ("not allowed") and under the POA&M; the score
  threshold (88) and 180-day closeout are stated beside it. `hound ssp build` loads the bundled methodology for this profile.
- Snapshots (`--snapshot-out`) keep the category, family and flags, so a signed CMMC plan rebuilds to the same hash.
- Functional: `SspFunctionalTests.Renders_the_cmmc_level_2_plan_with_the_annex_by_family_and_the_poam_rules` builds the example's own
  CMMC plan against the seeded `EX-CMMC-2026` (14 families, 110 requirements, AC.L1-3.1.1 flagged); result recorded once CI runs it.

### s17-05 SPRS score (added 2026-11-24)
- [ ] Done

**Story:** As a supplier holding CUI, I want my NIST SP 800-171 DoD Assessment Methodology score worked out from the audit, so that what
I enter in SPRS matches my evidence.

**Acceptance criteria**
- `hound sprs score` computes the score from the CMMC Level 2 audit with the methodology's weights (starting at 110, 5, 3 or 1 point per
  unmet requirement, and the partial credit rules where the methodology gives them), listing each deduction with its requirement and
  evidence. The weights live in a data file with its source cited, not in code.
- The score, its date and the POA&M (s17-03) it depends on are written to CISO Assistant as evidence on the audit, so the committee and
  board reports (s12) show it and its trend.

**Tests first**
- `SprsScoreTests.Unmet_requirements_deduct_their_weights`
- `SprsScoreTests.Weights_come_from_the_data_file`

**Functional check**
- `hound sprs score` against the example CMMC audit prints the score and its deductions.

**Notes**
- Weights: `frameworks/sprs/dod-assessment-methodology-1.2.1.yaml`, Annex A of the NIST SP 800-171 DoD Assessment Methodology,
  Version 1.2.1, June 24, 2020 (pages 12 to 20), copied value by value; 110 requirements, lowest score -203. `SprsMethodologyReader`
  allows only 5, 3, 1 or `none` (3.12.4).
- Scoring (`SprsScoring`, pure): compliant and not applicable rows take nothing off; partially compliant, not assessed and missing rows
  take the full points. For 3.5.3 and 3.13.11 the 3-point case is named for a person to judge, never assumed. Without a compliant
  3.12.4 the score is flagged: an assessment could not be completed.
- `hound sprs score --audit --config [--methodology] [--control] [--format json]`; `--control` uploads the score as evidence
  `hound-sprs/<audit>-<date>` on an applied control, as `hound report snapshot --control` does. The score on the committee and board
  reports, and the POA&M beside it, wait for s17-03 (see Discovered work).
- Guide `docs/adopt/cmmc-level-2.md`, skill `keep-the-sprs-score` (agent `hound-operations`), cheat sheet. Functional:
  `SprsFunctionalTests` scores the seeded `EX-CMMC-2026` and checks the result against the audit's own rows.

**Notes**
